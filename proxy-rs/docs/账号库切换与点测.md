# 账号库模式：点测与切换

这篇讲两件事：切换前怎么在隔离环境里把功能点一遍，以及怎么把 proxy-rs + Docker kiro-rs 切成账号库模式。设计背景见改造方案 §0。

> **本机已于 2026-09-29 切换完成**：Docker 容器、镜像和 compose 文件已移除，旧账号文件已清理。下文第三、四节保留作记录；回滚见"回滚"一节（不再依赖 Docker）。

先分清三个位置：

| 位置 | 是什么 |
|---|---|
| `~/kiro-rs/config/` | kiro-rs 的 `config.json`（端口、Admin Key）和旧的 `credentials.json` |
| `~/kiro-rs/data/accounts.sqlite3` | 账号库：所有账号、凭据、额度、统计。**含全部 token** |
| `~/Library/Application Support/proxy-rs/` | proxy-rs 的 userData：设置、分组、`account-db.json` 开关 |

## 一、构建

```bash
cd ~/cache/AI/kiro-rs/proxy-rs
npm run dist:current        # 先构建 kiro-rs，再打本机架构的 .app（dist/mac-arm64/）
```

产物里 `Proxy RS.app/Contents/Resources/kiro-rs` 就是会被拉起的反代。

## 二、隔离环境点测（不碰正在用的数据）

隔离环境有自己的 userData、自己的账号库、自己的端口，和正在跑的 proxy-rs / Docker kiro-rs 互不影响。

### 准备

```bash
export T=/tmp/proxy-rs-pointtest
mkdir -p $T/kiro $T/cli
# 复制一份 kiro-rs 配置，把端口改成没被占用的（例如 12999）
cp ~/kiro-rs/config/config.json $T/kiro/config.json
python3 - <<'EOF'
import json; p='/tmp/proxy-rs-pointtest/kiro/config.json'
c=json.load(open(p)); c['port']=12999; json.dump(c, open(p,'w'), indent=2)
EOF
echo '[]' > $T/kiro/credentials.json
cat > $T/account-db.json <<EOF
{"enabled":false,"dbPath":"$T/data/accounts.sqlite3","kiroRs":{"configPath":"$T/kiro/config.json","manage":true}}
EOF
APP="$HOME/cache/AI/kiro-rs/proxy-rs/dist/mac-arm64/Proxy RS.app/Contents/MacOS/Proxy RS"
PROXY_RS_USER_DATA_DIR=$T "$APP" --migrate-account-db=apply      # 建一个空库
```

CLI 切号也要隔离，否则会改掉你真实的 kiro-cli 登录：

```bash
sqlite3 $T/cli/data.sqlite3 "CREATE TABLE auth_kv (key TEXT PRIMARY KEY, value TEXT); CREATE TABLE state (key TEXT PRIMARY KEY, value TEXT);"
```

启动：

```bash
PROXY_RS_USER_DATA_DIR=$T KIRO_CLI_DB_PATH=$T/cli/data.sqlite3 "$APP"
```

用一个你不在乎的账号在这个隔离 App 里重新登录（社交和 BuilderId 各一个最好）。

### 逐项点测

| # | 操作 | 期望 |
|---|---|---|
| 1 | 启动后打开 `http://127.0.0.1:12999/admin` | 能登录；头部有"仅号池 / 全部账号"按钮 |
| 2 | 在隔离 App 里登录一个账号 | 账号卡片出现；约 1 分钟内额度、订阅自动填好（kiro-rs 首次查额度） |
| 3 | Admin 页切到"全部账号" | 能看到刚登录的账号，带"未入池"徽标 |
| 4 | 账号卡片点云图标（加入号池） | 图标变绿常亮；Admin"仅号池"列表出现它 |
| 5 | 用 `curl` 或客户端向 12999 发一条请求 | 正常返回；Admin 上该账号成功次数 +1 |
| 6 | 再点云图标（移出号池） | 图标变灰；Admin"仅号池"里消失，"全部账号"里还在；账号卡片不受影响 |
| 7 | 账号卡片点"刷新 Token" | 成功；日志里是 `[AccountDb]` / kiro-rs 在刷新，proxy 不调上游认证接口 |
| 8 | 账号卡片点"检查状态" | 额度明细（基础 / 试用 / 奖励）完整显示 |
| 9 | 打开账号详情 → 模型列表、订阅计划 | 能正常加载 |
| 10 | 编辑账号：改昵称、换分组、打标签 | 保存后生效；凭据区域是只读的并有提示；没有"首选端点"了 |
| 11 | 导出（勾"包含凭据"） | 导出文件里有 refresh token；普通列表里看不到明文（DevTools 里 `window.api.loadAccounts()` 的 credentials 只有 `hasAccessToken` 之类） |
| 12 | 切号到 Kiro CLI | 成功；`sqlite3 $T/cli/data.sqlite3 "select key from auth_kv"` 有对应的 token 键 |
| 13 | 等 token 临期（或在 Admin 上点该账号"刷新"） | 日志出现 `[KiroCLI] 已把账号 … 的新凭据同步给 CLI`；CLI 库里的 refresh_token 跟着变 |
| 14 | 在 CLI 库里手动改 refresh_token，再触发一次刷新 | 日志出现"停止自动同步"，CLI 库里保持你改的值 |
| 15 | 退出 App（菜单 Quit） | `pgrep -fl "kiro-rs .*proxy-rs-pointtest"` 没有输出 |
| 16 | 重新打开，再 `kill -9` 掉 kiro-rs 进程 | 几秒内自动重启；账号卡片数据照常显示 |
| 17 | `kill -9` 掉 App 主进程 | kiro-rs 随之退出，不留残留进程 |
| 18 | 删除账号 | 账号卡片消失；Admin"全部账号"里也消失 |
| 19 | 同一账号重新登录一次 | 不会出现第二个同邮箱账号；原卡片的凭据被替换 |
| 20 | `ls $T/data/backups` | 有当天的 `accounts-YYYY-MM-DD.sqlite3`，权限 `-rw-------` |

点测结束：

```bash
mv /tmp/proxy-rs-pointtest ~/.Trash/proxy-rs-pointtest.$(date +%s)
```

## 三、切换本机

整个过程约 10 分钟，每一步都能回头。

1. **退出** 正在运行的 proxy-rs（菜单 Quit，不是关窗口）。
2. **停掉 Docker 里的 kiro-rs**：`cd ~/kiro-rs && docker compose down`。迁移期间不能有进程在刷新这些 token。
3. **安装新版**：把 `dist/mac-arm64/Proxy RS.app` 拖进 `/Applications` 覆盖。
4. **预览迁移**（只读）：

   ```bash
   "/Applications/Proxy RS.app/Contents/MacOS/Proxy RS" --migrate-account-db
   ```

   重点看输出里的"无法导入"和"冲突"两项。无法导入的账号会留在本地、不进账号库，要手动处理（多半是缺 Refresh Token 或 IdC 缺 Client Secret）。

5. **执行迁移**：

   ```bash
   "/Applications/Proxy RS.app/Contents/MacOS/Proxy RS" --migrate-account-db=apply
   ```

   先把 electron-store 文件、`credentials.json`、`kiro_stats.json` 备份到 `~/kiro-rs/data/migration-backup-*/`，然后建库并打开账号库模式。原文件不改、不删。

6. **正常打开** proxy-rs。它会拉起 kiro-rs（只监听 127.0.0.1:12888），把"启动后导入"的账号交给 kiro-rs。
7. **复验**：按上面点测表的 1、4–9、15 挑几项；`docker ps` 里没有 kiro-rs。
8. **观察一两天**没问题后，清理旧文件（见下节）。

### 回滚

1. 退出 proxy-rs。
2. `"/Applications/Proxy RS.app/Contents/MacOS/Proxy RS" --rollback-account-db`：库里最新的凭据写回 electron-store，在 `~/kiro-rs/config/` 生成 `credentials.rollback-*.json`，账号库模式关闭。
3. 装回旧版 App。Docker 已移除：要恢复 Docker 部署，需把废纸篓里的 `kiro-rs-docker-compose.*` 目录中的 `docker-compose.yml` 放回 `~/kiro-rs/`，重新 `docker build` 镜像，用 rollback 文件替换 `credentials.json` 后 `docker compose up -d`。

不要用迁移前的备份回滚：账号库模式下 token 可能已经轮换过，旧备份里的 refresh token 会失效。

## 四、清理旧文件

切换后 `~/kiro-rs/config/` 里的 `credentials.json`、`kiro_stats.json`、`kiro_balance_cache.json`、`kiro_credit_cursors.json` 和那几十个 `.bak-*` / `.before-*` 都不再被读取，但都含历史 token。

```bash
bash ~/cache/AI/kiro-rs/proxy-rs/scripts/cleanup-legacy-kiro-files.sh           # 只核对、列出
bash ~/cache/AI/kiro-rs/proxy-rs/scripts/cleanup-legacy-kiro-files.sh --apply   # 移入废纸篓
```

脚本先核对：账号库完整、schema 版本对、Docker 里没有 kiro-rs 在跑、`credentials.json` 里每个凭据 ID 都已在账号库中——任一不通过就中止。只动账号相关文件，`config.json` 和它的备份不动。文件移进废纸篓里的一个独立目录，确认没问题后清空废纸篓即可。

迁移时生成的 `~/kiro-rs/data/migration-backup-*/` 同样含 token，确认不再需要回滚后也可以移进废纸篓。

## 日常

- 账号库每天自动备份到 `~/kiro-rs/data/backups/`，保留 7 份。恢复：退出 proxy-rs，把备份复制成 `accounts.sqlite3` 再打开。备份里的 refresh token 可能已被轮换作废，恢复后个别账号可能要重新登录。
- 账号需要重新登录时，直接在 App 里重新登录同一个账号即可：会替换原账号的凭据，不会多出一个账号。
